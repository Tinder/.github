# Organization profile guidance

Scope: `profile/README.md`, the public Tinder GitHub organization profile.

- Preserve the existing mission, brand artwork and friendly tone. Use GitHub's
  native Markdown styling, emoji-prefixed level-three section headings and
  ordinary text links. The README itself is the rendered reference for these patterns.
- Do not use em dashes in profile copy. Separate headings, descriptions and links
  with paragraph breaks instead.
- Keep the engineering blog prominent near the top, with its own heading, a short
  description and a clear link. Use the destination URL without tracking parameters.
- Keep the brand image compact so it does not push the introduction and blog far
  down the page. The current width is 320 pixels, constrained by GitHub on mobile.
- Describe enduring engineering challenges. Avoid dated launch roundups, rollout
  promises, product-status claims and performance statistics unless their current
  accuracy and public suitability have been verified. Link to the blog for stories.
- Check the rendered README at desktop and narrow mobile widths after layout edits.
  Keep changes in a pull request for owner review; do not merge without approval.
